# Ограничение частоты заявок UniForm21

Добавлено 13 октября 2026 в дистрибутив модуля. Включено в релиз 2.1.0.

## Правила по умолчанию

- До60POST-попыток за300секунд на один IP, суммарно для форм одного сайта.
- До5заявок, прошедших валидацию и допущенных к почтовому обработчику, за600секунд.
- Не менее15секунд между такими заявками. Ошибки заполнения не расходуют этот лимит, но считаются POST-попытками.
- Открытие формы GET не считается попыткой. Новые cookie/сессии и переключение формы не сбрасывают квоту IP.

Нельзя считать эти заявки доказанно доставленными письмами: резервирование происходит **до** почтового обработчика, поэтому его отказ также расходует квоту. Повторная отправка после таймаута может быть ограничена; автоматический повтор POST не выполняется.

## Настройка

Только доверенный config.tpl формы:

```text
rateLimitRequests = 60
rateLimitRequestWindow = 300
rateLimitSubmissions = 5
rateLimitSubmissionWindow = 600
rateLimitInterval = 15
```

Квоты ограничены диапазоном1–1000, окна1–3600секунд, интервал0–3600. Ноль у интервала убирает только паузу, не квоты. Эти параметры из GET/POST не принимаются. Для согласованного поведения задавать одинаковые правила во всех формах сайта: хранилище по IP общее, а значения правил берутся из конфигурации обрабатываемой формы.

## Ответ и хранение

- При блокировке возвращается обычная форма с alert, сохранёнными значениями и временем ожидания. HTTP200 сохранён для совместимости с существующими AJAX-клиентами; добавлен Retry-After. Это прикладной лимит, не серверный HTTP429/WAF.
- Состояние — небольшие JSON-файлы в системном временном каталоге, папка dle-uniform-{хэш ENGINE_DIR}. Внутри только UNIX-времена; имя файла — HMAC IP с SECURE_AUTH_KEY. Исходный IP/почта/текст заявки в файле не сохраняются. Для изолированных тестов без константы есть fallback на хэш ENGINE_DIR.
- flock делает резервирование атомарным; не удалось открыть/записать/заблокировать состояние — отправка запрещается с нейтральной временной ошибкой.
- Каталог/файл создаются с0700/0600 на системах, где это поддерживается. На Windows действуют также ACL временного каталога; права проверять при размещении на сервере.
- Старые временные файлы автоматически не удаляются: окна истекают при обработке, но файлы остаются. Администратор может настроить очистку неактивных файлов этой конкретной папки старше2часов. Удаление свежего состояния/перезапуск с очисткой temp сбрасывает квоты.

## Ограничения

REMOTE_ADDR используется напрямую, заголовки X-Forwarded-For не доверяются. За reverse proxy нужно корректно настроить реальный адрес клиента на уровне сервера; иначе пользователи одного прокси попадут в общую квоту. Общий IP/NAT также разделяет квоту. Лимит локален для одного экземпляра; нескольких серверов с независимыми temp он не объединяет.

Это ограничение отправок, а не CAPTCHA/антивирус/полная защита от распределённого спама или DoS. PHP принимает тело/загрузки до выполнения модуля, и при блокировке модуль продолжает обработку для повторного вывода формы. Серверные ограничения размера/частоты HTTP-запросов проверяются отдельно.

Дополнительно исправлена совместимость с jquery.form: пустое attachments[] в POST удаляется как пустой placeholder. Непустые массивы не разрешаются этим исключением, пути/содержимое из POST не становятся вложениями; реальные файлы обрабатываются через $_FILES с прежней проверкой типа и размера.

При установке заменить functions.php,uniform.php,cfg.php вместе и заново открыть формы: параметры конфигурации изменяют контекст CSRF/кэша. В пересобранный UniForm21 2.1.0 включены этот этап и CHANGELOG.md.
